API reference

          
Three endpoints. JSON in, JSON out. No SDK required.

        


        

          

            POST
            /api/verify
            Verify a single receipt
          

          

            POST
            /api/verify/batch
            Verify up to 10 receipts in parallel
          

          

            GET
            /health
            Service status and demo-mode flag
          

        


        

          

            

              
              
              
              
            


            

              
curl -X POST http://localhost:5000/api/verify \
  -H "Content-Type: application/json" \

    "receipt": "CJP9OSP9WZ",

const res = await fetch("http://localhost:5000/api/verify", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    receipt: "CJP9OSP9WZ",
    defaultVerification: true,
  }),
});

const data = await res.json();

if (res.ok) {
  console.log(data.message); // genuine
} else {
  console.error(data.error); // "Mismatch on amount..."
}

            


            

              
import requests

res = requests.post(
    "http://localhost:5000/api/verify",
    json={
        "receipt": "CJP9OSP9WZ",
        "defaultVerification": True,
    },
    timeout=30,
)

if res.ok:
    print(res.json()["message"])
else:
    print("Rejected:", res.json()["error"])

Why it is built this way

          
Small, auditable and fast enough for checkout flows.

        


        

          

            ⚡
            
Parallel batch verification

            

              Connection pooling and HTTP pipelining via undici,
              with configurable concurrency. Roughly 10–15× faster than
              sequential checks.
            

          


          

            🔍
            
Field-level control

            

              Check only what matters for a given payment — amount, recipient
              name, account number, date, or transaction status.
            

          


          

            🛡️
            
Typed and defensive

            

              TypeScript throughout, explicit timeouts, and distinct error
              classes so a bank outage never looks like a failed payment.
            

          


          

            🧪
            
Offline demo mode

            

              Exercise the whole pipeline with synthetic receipts when you have
              no network or no real receipt to hand.
            

          


          

            🐳
            
Docker ready

            

              Multi-stage image, runs as a non-root user, configured entirely by
              environment variables.
            

          


          

            🔓
            
MIT licensed

            

              Clone it, fork it, ship it inside your own product. No keys, no
              accounts, no per-call pricing.
