Integration

Verify from your app

POST a receipt reference, get a verdict. Receipt IDs and full receipt URLs are both accepted, and the provider is auto-detected.

terminal 
# One call, one verdict
curl -X POST http://localhost:5000/api/verify \
  -H "Content-Type: application/json" \
  -d '{
    "receipt": "CJP9OSP9WZ",
    "defaultVerification": true
  }'

# 200
{ "message": "The receipt 'CJP9OSP9WZ' is a valid receipt." }
const res = await fetch(`${API}/api/verify`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    receipt: "CJP9OSP9WZ",
    defaultVerification: true,
  }),
});

const data = await res.json();

if (!res.ok) {
  // "Mismatch on amount. Expected: 100, Actual: 999.00"
  throw new Error(data.error);
}

// Safe to fulfil the order
console.log(data.message);
import requests

res = requests.post(
    f"{API}/api/verify",
    json={
        "receipt": "CJP9OSP9WZ",
        "defaultVerification": True,
    },
    timeout=30,
)

if not res.ok:
    # Reject the order — do not hand over goods
    raise ValueError(res.json()["error"])

print(res.json()["message"])
<?php
$ch = curl_init("$apiBase/api/verify");

curl_setopt_array($ch, [
  CURLOPT_POST           => true,
  CURLOPT_RETURNTRANSFER => true,
  CURLOPT_HTTPHEADER     => ["Content-Type: application/json"],
  CURLOPT_POSTFIELDS     => json_encode([
    "receipt"             => "CJP9OSP9WZ",
    "defaultVerification" => true,
  ]),
]);

$body   = json_decode(curl_exec($ch), true);
$status = curl_getinfo($ch, CURLINFO_HTTP_CODE);

if ($status !== 200) {
  throw new Exception($body["error"]);
}

What you get back

  • 200 — every enabled field matched
  • 400 — a field mismatched, with both values
  • 404 — receipt not found upstream
  • 502 / 504 — bank unreachable or timed out

Failures are separate from outages on purpose. A bank being down must never read as a customer's payment being fake.

Verification modes

Single checks and batch runs

Both modes use the same validator, so a batch result is exactly as strict as a single one.

01

Single verification

Check one receipt in real time. Ideal for confirming payment before you hand over goods or unlock access.

POST /api/verify Field-level control
02

Batch verification

Submit many references at once. Every item gets its own result, so one bad receipt never hides the others.

POST /api/verify/batch Concurrent, up to 10
